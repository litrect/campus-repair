# A2 评审记录与任务拆解 0.2

评审对象：已上传《校园线上报修与后勤服务系统 需求规格说明书》V1.0。此清单把原文已确定事项、实现缺口和待团队决定事项分开，避免把建议误写成既定需求。

## 1 已确认的需求基线

- 三种角色：学生、维修工、管理员；后端实施 RBAC（2.2、3.1 FR-16、4 NFR-04）。
- 四张核心表：`user`、`repair_order`、`order_log`、`evaluation`（5.5）。
- 六个工单状态及八条迁移规则；改派状态不变但版本递增（5.3.1 至 5.3.4）。本稿的 CREATE/OVERTIME 日志事件是实施细化。
- 提交报修、派单、维修、确认评价等主流程及异常流程（3.3）。
- MySQL 8、Flask、PyMySQL；不依赖外网（2.3、5.1）。
- 图片最大 2 MB、重复点击只建一单、评价每单最多一条、约 50 人在线（3.3、4、5.5）。

## 2.1 对首版交付的修正

| 问题 | 0.2 修正及证据 |
| --- | --- |
| 维修工能否读历史改派工单前后不一致。 | 统一仅当前维修工可读，API 归属检查与验收用例同步。 |

## 5 最低验收清单

1. MySQL 8.0.16+ 空库执行 `schema.sql` 成功；四张表、外键、唯一键、检查约束存在；`seed.sql` 可插入四个演示用户。
2. 正常流程 `CREATED → ASSIGNED → PROCESSING → DONE → CLOSED` 每步成功，日志与工单事务一致。
3. `CREATED → CANCELLED`、`ASSIGNED → CANCELLED`、`ASSIGNED → ASSIGNED` 改派、`DONE → PROCESSING` 驳回均按角色、归属和版本校验。
4. 两个管理员同版本派单、改派时仅一个成功；失败者得到 409，工单与日志不产生半成品。
5. 重复提交同一 `Idempotency-Key` 只生成一单；同键不同请求体返回冲突。
6. 学生不能读取或修改他人工单；维修工不能处理未分配给自己的工单；角色越权由后端拒绝。
7. 重复评价被唯一键和业务层共同阻止；评分 0、6 被拒绝。
8. 图片大于 2 MB、缺少必填字段、空维修记录、空驳回原因均得到明确错误。
9. 超时边界测试覆盖恰好到期、到期后未完成、到期后完成、驳回后再维修；以冻结的 SLA 口径断言。
10. 管理员统计与评价汇总使用一致的时间范围和工作量口径。
