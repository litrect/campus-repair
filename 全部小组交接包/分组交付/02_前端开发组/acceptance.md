# A2 需求追踪与验收用例

版本 0.2。原说明书的 FR/NFR 编号保持不变。本文件新用例使用 A2-T 编号，避免与原说明书未提供完整内容的 TC 编号混淆。以下是系统联调验收计划；不因数据库验证通过就自动标为通过。

## 可执行的系统验收步骤

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| A2-T01 | 学生提交合法表单，不上传图片。 | HTTP 201、code=0；一张 CREATED 工单、version=0、一条 CREATE 日志；student_id 来自登录用户。 |
| A2-T02 | 缺 location、全空白 description、未知 category、无效 urgency、传入 studentId 或 status。 | HTTP 400，数据库工单与日志数量不变。 |
| A2-T03 | 并发发送两次相同学生、幂等键、表单；再以该键改 description。 | 前两次返回同一 ID，只有一单一条创建日志；不同内容请求返回 409。不同学生相同键不互相影响。 |
| A2-T04 | 学生 A 查自己的列表，再请求学生 B 的详情、日志和图片；改派前维修工再读已改派工单。 | 列表仅本人；跨归属资源返回 404，不能泄露描述或手机号；原维修工改派后也返回 404。 |
| A2-T05 | 准备 CREATED、ASSIGNED、CANCELLED 工单查询待派列表。 | 仅 CREATED 出现；分页 total 与数据库匹配，排序稳定。 |
| A2-T06 | 管理员派给启用维修工，再尝试不存在、学生角色或停用账号。 | 有效派单更新 ASSIGNED、worker_id、assign_time、version 与日志；无效目标 422，工单不变。 |
| A2-T07 | 两个管理员使用同一 version 同时派给不同维修工。 | 恰有一个成功，另一个 409；只增加一次版本和一条派单日志。 |
| A2-T08 | 对 ASSIGNED 工单改派给另一维修工；重复使用旧 version；再对 PROCESSING 工单改派。 | 首次状态仍 ASSIGNED、版本加一，日志记原/新维修工；旧版本和非法状态均 409。 |
| A2-T09 | 当前维修工接单；他人接单；重复旧版本接单。 | 正确接单进入 PROCESSING 并写 accept_time；他人 404，重复版本 409。 |
| A2-T10 | PROCESSING 工单提交空维修记录，再提交 1–500 字符有效记录。 | 空记录 400；有效记录进入 DONE，完成时间与本次日志一致，历史记录可追溯。 |
| A2-T11 | 本人学生确认 DONE 工单；之后再次确认。 | 首次 CLOSED、close_time 与版本更新；重复确认 409，不增加重复日志。 |
| A2-T12 | DONE 工单缺原因驳回，再提交有效原因；维修工重新完成。 | 缺原因 400；有效驳回 PROCESSING、finish_time 清空、deadline 不变；旧完成记录和时间仍在日志，新完成记录另增日志。 |
| A2-T13 | 学生取消本人 CREATED、尝试取消 ASSIGNED；管理员分别取消 CREATED 和 ASSIGNED；尝试取消 PROCESSING。 | 学生仅第一种成功，管理员前两种成功；其余 409；取消状态 CANCELLED，close_time 为空，取消时刻在日志。 |
| A2-T14 | 运行正常流程和一次改派/驳回，查询日志。 | order_version 从 0 连续递增且无重复；每条状态符合迁移表，系统超时操作人为空，人工操作人正确。 |
| A2-T15 | 在状态更新后、日志插入前模拟数据库错误。 | 整个事务回滚，状态、维修工、版本和日志均保持操作前值。 |
| A2-T16 | CLOSED 工单评价 5 分后再评；尝试 0、6、true、非本人工单、未 CLOSED 工单。 | 首次成功；重复 409；无效评分 400，跨归属 404，未关闭 409；只留一条合法评价。 |
| A2-T17 | deadline 前 1 秒、恰好到期、到期后 1 秒查询；晚完成发生在两次扫描之间。 | 前两者不超时，后一种超时；完成动作自身将标记置 1，不依赖扫描已发生。 |
| A2-T18 | 截止前完成后晚确认；截止后驳回；两次扫描重复运行；超时后取消。 | 等待确认本身不算超时；晚驳回即判超时且不延长期限；标记只首次更新一次；取消后不在 active 列表但可在 history 列表。 |
| A2-T19 | 维修工甲有评分 5 和 3，乙没有评价，某 CLOSED 工单未评价。 | 甲平均 4.00、评价数 2；乙平均 null；未评价不按 0 分计；列表数量与汇总一致。 |
| A2-T20 | 两张提交工单，一张在查询区间内关闭；每单多条日志；from/to 边界各有记录。 | created/completed 分别按 create_time/close_time 计数；不因日志重复；from 包含、to 排除；维修工分组总数可核对。 |
| A2-T21 | 正确/错误密码、无 token、过期 token、错误签名、停用用户旧 token。 | 正确登录成功；其他 401 或统一登录错误；任何响应均不含 password 哈希。 |
| A2-T22 | 学生调用派单/统计、维修工调用确认评价；前端隐藏按钮后直接请求 API。 | 角色越权返回 403；后端独立验证，不能靠前端隐藏保护。 |
| A2-T23 | 上传合法 PNG/JPEG，恰好 2 MiB、超过 1 字节、伪装扩展名、任意路径或他人图片地址。 | 合法且不超限可用；超限 413，格式/路径/归属不合法被拒绝；未创建工单不能成为他人可读取的图片。 |
| A2-T24 | 断开外网在演示机打开全部页面、登录、上传与完成报修；验证站内轮询提示。 | 页面资源本地加载，核心流程不依赖外网；待派/新派/待确认/超时提示可随列表更新。 |

## 非功能需求追踪

| 需求 | 验收方法 | 当前状态 |
| --- | --- | --- |
| NFR-01 普通页面响应小于 2 秒 | 演示机上记录关键页面请求耗时，覆盖列表、详情和常用操作，记录数据规模与最慢值。 | 待应用实现后测量。 |
| NFR-02 约 50 人在线 | 用 50 个独立用户会话混合执行查询和合法操作，记录响应、错误率与冲突提示。 | 待应用实现后测量。 |
| NFR-03 非明文密码 | 验证库中四账号为可验证哈希；检查登录响应不泄露密码字段。 | 数据库部分已验证，API 待验收。 |
| NFR-04 后端越权拦截 | A2-T04、21、22。 | 待应用实现。 |
| NFR-05 明确提示与简短流程 | 按四张时序图走通页面，错误可理解，冲突后可刷新。 | 待页面验收。 |
| NFR-06 分层与版本管理 | 审核路由/服务/数据访问职责，所有状态写入经过统一入口，检查 Git 提交记录。 | 设计已给出，实现待审核。 |
| NFR-07 Chrome/Edge | 两种浏览器分别走 A2-T01 至 24 的关键页面及手机尺寸。 | 待页面验收。 |
| NFR-08 并发一致性 | A2-T07、08、15，以及 SQL DB14 并发派单验证。 | 数据库模式已通过，API 端到端待验收。 |

验收记录应填写测试人、日期、环境、实际结果和缺陷号。A2 负责设计一致性，后端组完成服务实现，测试组执行端到端用例；设计文档存在不等同于功能已开发。
