# 测试与质量组交接说明

交付方：A2 系统设计与数据库负责人。版本：A2 修订稿 0.2；分组日期：2026-10-12。本包已包含本组必读内容与必要参考文件，解压后从本说明开始。

## 阅读顺序

1. [acceptance.md](acceptance.md)：按 24 个用例执行并记录实际结果。
2. [verification-report.md](verification-report.md)：了解已经完成的数据库检查及其范围。
3. [api-contract.md](api-contract.md)：作为请求参数、权限、响应和错误码的测试依据。
4. [implementation-notes.md](implementation-notes.md)：核对并发、幂等和超时边界。
5. [verify_delivery.py](verify_delivery.py)：在独立新测试库复现数据库验证。

## 本组任务

- 建立三个角色的测试账号和可重复使用的工单数据，记录环境与后端版本。
- 覆盖全部 16 条功能和 8 条非功能需求，执行 acceptance.md 的 A2-T01 至 A2-T24。
- 重点检查跨用户读取、角色越权、双人同时派单、旧版本改派、重复提交与重复评价。
- 验证驳回后再次完成、恰好到期与到期后、扫描间隙完成、重复扫描和取消后的超时归属。
- 在应用实现后执行 50 人在线、页面响应、浏览器兼容和断网演示测试。

## 完成标准

每条需求都有验收结果；失败用例关联缺陷；回归完成后给出结论。已有 17 项数据库验证结果仅作为参考证据，不能替代端到端测试。

## 需要回交给 A2 的内容

- 逐条填写的测试结果：测试人、日期、环境、前提、输入、实际结果和通过/失败。
- 缺陷清单：复现步骤、期望与实际、接口响应或截图、严重程度和回归状态。
- SQL 验证结果、性能与兼容性记录，以及验收结论。

SLA 建议 4/24/72 小时、故障分类、推荐权重和 token 有效期均需小组确认。各组汇总修改意见，由 A2 更新统一基线后重新分发。说明中没有写成通过的测试均需实际执行。

Markdown 文件用于阅读设计与说明；SVG 是图稿；Mermaid 是图源。SQL 和数据库验证脚本随后端、测试包提供。分组复制保留原文件名，以保证文档链接和验证脚本可用。
