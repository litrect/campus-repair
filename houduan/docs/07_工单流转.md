## 统一事务入口

所有本次新增工单更新通过 services/workflow_service.py 的 change_status。客户端只能调用具体动作，不接受目标 status。

业务层再次核验动作角色、工单归属、客户端版本和合法状态，随后构造服务器控制的字段更新。UPDATE 条件包含 id、旧 status、客户端 version；维修工动作额外包含 worker_id。影响行数必须恰好为 1，否则返回 409。每次成功版本加一，按新版本写唯一日志。

整个动作使用一个事务，统一提交或回滚；固定同一个事件时间写工单时间字段和日志。日志插入失败会回滚状态、维修工、记录、时间、超时标记和版本。死锁或锁等待超时回滚完整事务，返回可重试的 503；不单独重试日志。

version 必须是整数 0～2147483646，不接受布尔值。数据库工单版本到达上限时停止后续修改并记录错误。

## 状态与权限

- CREATED → ASSIGNED：管理员派给存在且启用的 WORKER。读取目标用户使用 FOR SHARE 共享锁，校验期间阻止并发停用或角色变更抢先提交。
- ASSIGNED → ASSIGNED：管理员改派给另一位启用维修工；日志记录旧/新维修工，版本递增，重新写 assign_time。
- ASSIGNED → PROCESSING：当前维修工接单，写 accept_time。
- PROCESSING → DONE：当前维修工填写 1～500 字符非空维修记录，写 finish_time，记录同时保留在日志。
- DONE → CLOSED：报修学生确认，写 close_time。
- DONE → PROCESSING：报修学生提交 1～500 字符非空驳回原因；清空本轮 finish_time，保留最新维修记录和历史完成日志，deadline 不变。
- CREATED → CANCELLED：本人学生或管理员可取消；ASSIGNED → CANCELLED 仅管理员可取消。原因可省略，最多 500 字符；取消时刻写日志，不写 close_time。

PROCESSING 不允许改派或取消。角色越权 403；非本人/非当前维修工 404；旧版本、非法状态或改派给当前同一人 409；派给不存在、停用或非维修工用户 422。

## 派单推荐与超时

待派列表只返回 CREATED，使用统一分页及稳定排序。候选仅包含启用维修工；技能按逗号拆分后完整标签匹配，当前负载只计 ASSIGNED/PROCESSING。

推荐分=100×技能命中−10×当前负载。同分依次按负载升序、用户 ID 升序。权重集中在应用配置，管理员仍可手选任意启用维修工。

每次业务动作同步结算历史超时，严格大于 deadline 才超时；CONFIRM 按原 finish_time 判断，不把等待确认时间算入维修超时；REJECT 按驳回时刻与原 deadline 判断。曾超时标记不清除，不依赖扫描任务是否已运行。定时扫描在步骤 7 接入。
