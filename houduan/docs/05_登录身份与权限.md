# 步骤 4：登录、身份与权限

日期：2026-10-15。状态：登录及共用权限模块已实现。

## 登录接口

`POST /api/auth/login`，Content-Type 为 application/json。只接受 username、password 两个字段，拒绝缺失字段、未知字段、非对象请求体和错误类型；用户名去除首尾空白后不能为空且最长 50 字符；密码不去除空白。

请求示例：

```json
{"username":"stu1","password":"Demo@123456"}
```

成功 HTTP 200、code=0，data 含 token、expiresIn=28800，以及 user{id,realName,role}；id 为字符串。不返回密码哈希、手机号或数据库内部字段。

用户名不存在、密码错误、账号停用统一返回 HTTP 401，message 为“账号或密码错误”，避免通过提示判断账号是否存在。不存在用户名时仍执行密码哈希验证。

## Token 和接口角色

使用 itsdangerous 限时签名，载荷仅 {uid:字符串ID}，有效期 8 小时。密钥使用步骤 3 的本机持久化配置。签名无效、过期、载荷错误、用户不存在或停用均返回 401。

已注册的 API 路由默认需要 Authorization: Bearer token；公开例外仅为登录和两个健康检查。OPTIONS 预检不要求 Token。未知路由仍返回统一 404。

每次认证查询当前用户 ID、姓名、角色和启用状态，不从 Token 或请求体信任角色。角色权限使用 roles_required 装饰器，角色无权返回 403，先于业务请求体处理。

角色分工维持交接基线：学生提交本人报修、确认、驳回、评价；管理员派单、改派和统计；当前维修工接单和提交完成。具体业务路由在步骤 5～7 接入对应权限。

## 工单归属公共模块

services/access_control.py 提供 get_visible_order 和 ensure_order_visible：管理员可读所有工单，学生只读 student_id 为本人的工单，维修工只读当前 worker_id 为本人的工单。不存在与跨归属统一返回 404，同一错误响应不泄露工单信息。

后续详情、日志、评价和图片读取必须使用同一归属规则。当前已实现通用校验，并用仅在测试应用中注册的路由验证；实际工单和图片接口按后续步骤实现，不将测试路由发布到服务。
