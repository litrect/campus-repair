# 步骤 5：报修创建、图片与查询

日期：2026-10-15。状态：已完成。

## 已实现接口

除登录、健康检查与 OPTIONS 预检外，所有已注册业务接口均需 Authorization: Bearer token。

| 方法与路径 | 权限 | 用途 |
| --- | --- | --- |
| GET /api/meta/order-options | 已登录 | 分类与紧急程度选项 |
| POST /api/uploads/images | 学生 | multipart 的 file 字段上传一张 PNG/JPEG |
| GET /api/uploads/images/{studentId}/{filename} | 上传学生、管理员、相关当前维修工 | 读取本机图片 |
| POST /api/orders | 学生 | 提交报修，必须带 Idempotency-Key |
| GET /api/orders/my | 学生 | 本人报修分页查询 |
| GET /api/orders/assigned-to-me | 维修工 | 当前指派给本人的工单分页查询 |
| GET /api/orders/{id} | 按工单归属 | 完整详情，含评价字段 |
| GET /api/orders/{id}/logs | 按工单归属 | 按 order_version 升序的操作日志 |

加上登录，目前完成交接契约 20 个业务接口中的 8 个，以及图片读取接口；两项健康检查不计入业务接口。管理员待派列表和派单相关接口在步骤 6 实现。

## 创建与幂等

提交 JSON 包含 category、location、description，可选 urgency、imageUrl。服务端去除文本首尾空白、默认 NORMAL、图片缺省为 null，校验类别和长度，拒绝身份/状态等未知字段。学生 ID 来自登录用户。

Idempotency-Key 为 1–64 位 ASCII 字母、数字、下划线或连字符。对标准化创建字段按固定顺序序列化 UTF-8 JSON，计算 SHA-256 摘要。相同学生、键和标准化内容重试返回 HTTP 200 及原工单当前状态/版本；内容不同返回 409。不同学生同键互不影响。

首次创建返回 HTTP 201，状态 CREATED，version=0；与版本 0 的 CREATE 日志同一事务提交。数据库唯一键并发冲突时回滚并开启新事务读取原工单，避免使用旧快照。工单 UUID 编号碰撞单独处理，最多尝试 3 次。

创建时按 SLA HIGH/NORMAL/LOW=4/24/72 小时固定 deadline，工单和创建日志使用同一个秒级北京时间。

## 图片行为

单文件上限 2,097,152 字节，恰好等于上限允许，超过返回 413。校验真实 PNG/JPEG 内容并尝试完整解码，不依赖用户提供的扩展名；GIF、伪装图片和损坏内容拒绝。路径由服务端按 uploads/学生ID/随机UUID.png或.jpg 生成，拒绝任意外链、路径、他人图片引用和符号链接路径。

图片可由上传学生及管理员读取；维修工必须是引用该图片工单的当前指派人，未关联工单图片不能被维修工读取。鉴权失败返回 401，跨归属统一 404。前端须带 Bearer 请求获取 Blob 再显示图片。

## 查询行为

列表支持 page、pageSize、status；默认 1/20，pageSize 最大 100，拒绝未知或重复查询字段、非法状态及分页值。固定按 create_time DESC,id DESC 排序，返回 items、total、page、pageSize。

ID 均输出字符串，版本和分页计数为整数；时间带 +08:00。详情不暴露密码、手机号、请求幂等键或摘要。详情、日志统一校验学生/当前维修工/管理员权限。

列表和详情同时输出历史超时 isOvertime 与当前仍需处理的 isCurrentlyOverdue；边界为严格大于 deadline，已提交完成后的等待确认时间不增加维修超时。持久化超时扫描在步骤 7 实现。
