# 校园报修系统项目基线

版本：0.1；日期：2026-10-15；对应实施大纲步骤 1。

## 技术路线与依据

以 A2 修订稿 0.2 的后端交接包为设计依据，采用 Python 3.12、Flask、PyMySQL、MySQL 8.0.16+。认证使用 itsdangerous，密码使用 Werkzeug 哈希验证，图片内容使用 Pillow 校验；具体依赖版本在步骤 3 安装验证后锁定。

选择理由：交接包 review-and-tasks.md 将 Flask、PyMySQL、MySQL 8 列为需求基线，接口、种子密码与事务说明均围绕该方案设计。工作区另有 Spring Boot 3.2.5 / Java 17 旧项目，仅作参考，不直接作为新项目起点。

所有新增代码、配置、测试、运行数据和交付文档均保存在本文件所在的“houduan”根目录内。原交接资料保持原位，步骤 2 将审核后所需 SQL 纳入本项目。

## 开发默认业务规则

以下采用交接稿的具体建议，作为本项目可执行的开发基线；不表示需求组或其他小组已签字批准。后续业务调整需同步配置、接口、测试和本文件。

| 项目 | 本项目默认值 |
| --- | --- |
| 角色 | STUDENT、WORKER、ADMIN；每次请求核验账号启用状态及当前角色 |
| 报修分类 | 水电、门锁、网络、家具、其他；后端配置为唯一来源，前端通过 meta 接口读取 |
| 紧急程度与 SLA | HIGH=4 小时、NORMAL=24 小时、LOW=72 小时；默认 NORMAL |
| SLA 起止 | 创建时间起算，维修工提交完成为终点；创建时固化 deadline，改派和驳回不延长，配置变化不重算历史工单 |
| 超时边界 | 严格大于 deadline 才超时；等待学生确认不累计维修超时；驳回清空 finish_time，按原期限重新判定 |
| 超时维护 | 业务动作即时结算；后台每 60 秒扫描；仅首次 0→1 写超时日志并递增版本 |
| Token | itsdangerous 限时签名，载荷仅 uid，有效期 8 小时；密钥本地持久化；退出由前端清除 token，无单 Token 即时撤销功能 |
| 图片 | PNG/JPEG，单文件上限 2,097,152 字节；实际内容校验；本机受控存储，路径由服务端生成 |
| 图片访问 | 上传学生、管理员、关联工单的当前维修工可读；GET 同样鉴权，前端通过带 Bearer 头的请求获取 Blob |
| 推荐 | 100×技能完整标签命中−10×当前工单数；当前工单仅 ASSIGNED/PROCESSING；同分按工单数升序、ID 升序；管理员可手动选启用维修工 |
| 取消 | 学生仅取消本人 CREATED；管理员可取消 CREATED/ASSIGNED；原因可选，最多 500 字符 |
| 确认与评价 | 确认关闭后单独评价；整数 1–5，每单最多一次，不提供编辑、删除或评价期限 |
| 站内提醒 | 页面可见时每 30 秒轮询，离开停止；无独立消息收件箱和已读状态 |
| 统计 | 提交量按 create_time；完成量按 close_time 且仅 CLOSED；区间左闭右开；工作量归最终维修工；无评价平均分为 null |

## 核心实现约束

- 四张核心表：user、repair_order、order_log、evaluation。
- 主流程：CREATED → ASSIGNED → PROCESSING → DONE → CLOSED；支持 ASSIGNED 改派、DONE 驳回到 PROCESSING、CREATED/ASSIGNED 按权限取消；不支持维修中改派。
- 所有已有工单更新经统一业务入口，携带客户端 version，按 ID、旧状态和版本条件更新；工单与日志同一事务提交或回滚，日志只追加。
- 创建使用学生 ID + Idempotency-Key 唯一约束及标准化请求摘要；同键同内容返回既有工单，同键不同内容返回 409。
- 学生只读本人、维修工只读当前指派给本人、管理员可读全部；改派后原维修工失去访问权限。
- 按 api-contract.md 的 20 个业务接口和额外图片读取接口开发。成功 code=0，BIGINT ID 输出字符串，时间带 +08:00；未知字段拒绝，拒绝布尔值冒充整数。
- 所有连接使用严格 SQL 模式、显式业务事务及 +08:00 时区；仅使用参数化 SQL。
- 本地演示不依赖外网、CDN、短信或邮件。约 50 人在线、普通页面响应小于 2 秒作为后续实测目标。
