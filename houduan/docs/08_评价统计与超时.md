# 步骤 7：评价、统计与超时预警

日期：2026-10-15。状态：已完成，交接契约的 20 个业务接口均已实现；前端和最终系统验收继续按后续步骤执行。

## 新增接口

| 方法和路径 | 角色 | 参数 |
| --- | --- | --- |
| POST /api/orders/{id}/evaluate | 报修学生 | score，可选 content |
| GET /api/stats/evaluations | 管理员 | workerId、page、pageSize，可省略 |
| GET /api/stats/orders | 管理员 | metric、groupBy、from、to、category、status，可省略 |
| GET /api/orders/overtime | 管理员 | scope、page、pageSize，可省略 |

## 评价

工单必须 CLOSED 且属于当前学生。score 只接受整数 1～5，布尔值拒绝；content 可省略，提供时为最多 300 字符的字符串。

首次成功返回 HTTP 201，data.id 为字符串；重复评价通过数据库唯一键兜底，返回 409，不能修改或删除。评价在同一事务内核验归属、状态并新增，不修改工单版本或追加工单状态日志。

评价汇总只计算真实评价行，未评价工单不计 0 分，无评价平均分为 null。返回 averageScore、evaluationCount、分页 items/total/page/pageSize；平均分按原始评分算术平均并舍入到两位小数，JSON 数值不强制保留尾零。

## 工单统计

metric=created 为默认，按 create_time 统计；metric=completed 仅计 CLOSED，按 close_time 统计。groupBy 支持 category（默认）、status、worker、day。

from 包含、to 排除，可使用 ISO 日期或时间；无时区按 +08:00 解释，有时区转换为北京时间，开始不早于结束返回 400。缺省范围为全部时间，可按分类和状态过滤。未知参数、重复参数及非法枚举拒绝。

工单直接聚合，不与多条日志联表累计。维修工分组使用最终 worker_id，未指派 key 为 null；日期分组输出 YYYY-MM-DD。响应 total 与 buckets 计数总和一致。

## 超时查询

scope=active 为默认，只返回 CREATED/ASSIGNED/PROCESSING 且严格超过 deadline 的工单；scope=history 返回曾超时的工单，包括已完成、关闭或取消的工单。

历史查询使用缓存标记或有效时间判定：未完成看当前时间；DONE/CLOSED 看 finish_time；CANCELLED 看取消日志时间。因此扫描尚未更新时查询也不会漏掉真实超时。等待学生确认不累计维修超时，deadline=null 且无历史标记不算超时。

## 后台扫描

scripts/run_server.py 启动 API 时自动启动扫描，先运行一轮，再每 60 秒运行。任务只读取应用连接配置，不使用 root。

扫描按 ID 分批读取候选，通过统一 change_status 的 OVERTIME 系统分支执行版本条件更新。只有 is_overtime 从 0→1 才递增版本、写一条同状态的 OVERTIME 日志，operator_id=null；工单和日志同一事务。版本已改变则跳过，下一轮重新读取，避免覆盖人工操作。业务动作已标记的工单不重复写超时日志。失败项回滚并记录简洁错误，随后轮次可重试。

Windows 字节锁 instance/overtime.lock 保证同一项目实例只有一个扫描器；进程退出自动释放锁，锁文件保留不代表正在运行。重复启动同一对象、另一进程扫描或同时手动扫描均会被拒绝。

手动单轮扫描仅在 API 自动扫描停止时运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\scan_overtime.py
```

正常启动仍执行 scripts/start_backend.ps1。扫描结果写入 instance/logs/app.log，不记录密码、Token 或请求体。
