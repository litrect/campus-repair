## 3. 所有页面共同遵守的约定

### 请求与响应

登录以外的业务请求携带 `Authorization: Bearer <token>`。JSON 请求发送 Content-Type: application/json；图片上传用 multipart/form-data，交给浏览器生成 boundary，不要手写 Content-Type。健康检查公开，不需要 Token；OPTIONS 预检公开。

成功：HTTP 200/201，`{"code":0,"message":"成功","data":...}`。登录、动作等 message 可能不同，不要按 message 判断成功。失败：对应 HTTP 状态、非零 code，`data:null`。图片 GET 成功直接返回图片二进制，没有 JSON 包装；失败仍是 JSON。

| HTTP 状态 | 前端处理 |
| --- | --- |
| 400 | 显示字段/参数错误；修正表单，不自动重试 |
| 401 | 登录接口显示账号或密码错误；其他接口清除登录态并跳转登录 |
| 403 | 显示无权操作，检查当前角色；不要反复发送 |
| 404 | 显示不存在或不可访问；跨归属与不存在使用相同提示 |
| 409 | 工单版本/状态或重复评价冲突；先刷新详情，保留用户输入，由用户决定下一步；不要静默重放动作 |
| 413 | 提示图片超过 2 MiB |
| 415 | 检查 JSON Content-Type |
| 422 | 例如派单目标不存在、停用或非维修工；重新获取候选列表 |
| 500、503/网络中断 | 提示稍后重试；写操作可能已成功，先查询/刷新。仅报修创建可用原幂等键安全重试 |

所有 BIGINT ID 是十进制字符串，最大 9223372036854775807，不要 Number()/parseInt() 转换；路径与 workerId 也按字符串传。version、score、page、pageSize、total 是整数，布尔值不能代替整数。Boolean 字段是 JSON boolean，不是 0/1。

时间输出例：2026-10-15T12:30:00+08:00，显示时明确北京时间；不得把空时间显示成 1970 年。未知 JSON 字段返回 400，禁止直接提交整份详情对象：只组装接口允许的字段，尤其不能发送 studentId、operatorId、status、isOvertime。

### 登录态

Token 是不透明的签名字符串，不能按 JWT 解码或从中读取角色。登录成功保存返回的 token、expiresIn 和 user，建议使用 sessionStorage；切换账号/退出清除旧数据、列表、图片 Blob URL 和轮询。有效期 28800 秒（8 小时），后端仍以实际校验为准。前端角色只用于导航和按钮展示，后端每次读取当前角色与启用状态。

没有 /auth/me、注册、修改密码、刷新 Token 或服务端注销接口。前端退出为本地清除 Token；过期重新登录。当前用户展示使用登录返回的 user。

### 分页、筛选与提示

工单列表默认 page=1、pageSize=20；pageSize 为 1～100，page 为 1～2147483647。响应为 {items,total,page,pageSize}。筛选变更后页码回到 1。省略未选筛选条件，不传空字符串/null 字符串；未知或重复查询参数会被拒绝。列表按 createTime 降序、id 降序稳定排序。

站内提示用已有列表轮询和 total 徽标：页面可见时每 30 秒查询，隐藏/离开/退出后暂停；避免请求重叠。学生可轮询 my?status=DONE，维修工可轮询 assigned-to-me?status=ASSIGNED，管理员轮询 pending 和 overtime。没有独立消息收件箱、已读状态或 WebSocket。

### 字段约束

| 字段 | 约束 |
| --- | --- |
| username/password | 必填字符串；用户名 trim 后1～50字符；密码不 trim |
| category | trim 后属于 meta 返回值，最多20字符；当前水电/门锁/网络/家具/其他 |
| location/description | trim 后分别1～100/1～500字符 |
| urgency | HIGH/NORMAL/LOW，大小写严格；不传默认 NORMAL |
| imageUrl | 不传或 null，或原样使用本人上传返回的 URL；拒绝外链、任意路径、他人图片 |
| Idempotency-Key | 必填1～64位 ASCII 字母/数字/下划线/连字符，区分大小写 |
| workerId/路径 id | 正十进制整数字符串，非0、不超有符号 BIGINT |
| version | 必填 JSON 整数0～2147483646；不能是字符串或布尔值 |
| repairRecord/reject.reason | trim 后1～500字符 |
| cancel.reason | 可省略，提供时为最多500字符字符串，可为空；不要传 null |
| score/content | score 为整数1～5；content 可省略，提供时为最多300字符字符串；不要传 null |

### 主要返回模型

```ts
type ID = string;
type OrderStatus = 'CREATED'|'ASSIGNED'|'PROCESSING'|'DONE'|'CLOSED'|'CANCELLED';
interface Page<T> { items:T[]; total:number; page:number; pageSize:number }
interface OrderSummary {
  id:ID; orderNo:string; category:string; location:string;
  urgency:'HIGH'|'NORMAL'|'LOW'; status:OrderStatus; workerId:ID|null;
  createTime:string; deadline:string|null; isOvertime:boolean;
  isCurrentlyOverdue:boolean; version:number;
}
// OrderDetail = OrderSummary + 以下字段：
// description:string, imageUrl:string|null, repairRecord:string|null, studentId:ID,
// assignTime/acceptTime/finishTime/closeTime:string|null, evaluation:Evaluation|null
// Evaluation = {id:ID,score:number,content:string|null,createTime:string}
// OrderLog = {id:ID,eventType,fromStatus:OrderStatus|null,toStatus:OrderStatus,
//   orderVersion:number,operatorId:ID|null,fromWorkerId:ID|null,toWorkerId:ID|null,
//   remark:string|null,createTime:string}
// WorkerCandidate = {id:ID,realName:string,skill:string|null,
//   activeOrderCount:number,recommendationScore:number}
```

注意：工单详情没有 studentName/workerName/phone 字段；日志没有操作者姓名。不要假设这些字段存在。需要显示姓名时可从候选数据建立当前维修工映射；完整历史用户姓名查询需后端补充。

评价汇总 data：{workerId:string|null,averageScore:number|null,evaluationCount:number,items,total,page,pageSize}，items 为 {id,orderId,workerId,score,content,createTime}。不传 workerId 时按所有真实评价逐条平均；无评价为 null，展示“暂无评价”，不能显示为0分；前端可用 toFixed(2) 格式化非空均分。

统计 data：{metric,groupBy,total,buckets:[{key,count,workerName?}]}。metric 为 created（默认）或 completed；groupBy 为 category（默认）、status、worker、day。worker 的 key 是 ID 字符串或 null，day 是 YYYY-MM-DD；只有 worker 分组附 workerName。没有通用搜索、workerId 统计筛选或统计分页参数。

## 6. 两个最容易出错的联调点

### 幂等提交与版本冲突

报修表单首次提交时生成 crypto.randomUUID() 并保存本次字段快照及 key；超时/网络中断后重试使用相同 key、相同内容，直到得到确定结果。新一笔报修才生成新 key。同键不同内容返回409：先恢复/确认上一笔结果，再明确开启新提交，不要静默换键重复报修。提交按钮加载时禁用；仅禁用按钮不能替代幂等键。

```json
{"category":"水电","location":"A栋101","description":"水龙头漏水","urgency":"HIGH","imageUrl":null}
```

状态动作发送刚获取的详情 version。例如派单 body 为 `{"workerId":"2","version":0}`，示例 ID 仅演示。成功后使用响应新版本，并刷新详情、相关列表及日志。60 秒超时扫描也可能增加版本，因此即使只有一人在操作也可能返回409。不要在前端自行 version++，不要读取新版本后自动重放用户原操作。

### 图片上传和显示

每笔报修最多一张图片；可不上传。input accept 使用 image/png,image/jpeg；前端先检查大小不超过2097152字节，后端仍校验内容。先上传取得 imageUrl，再提交报修；上传成功但报修失败可继续引用同一图片，不要反复上传。当前没有图片删除/草稿清理接口。

```js
const form = new FormData();
form.append('file', selectedFile);
// 不手写 multipart Content-Type
const upload = await fetch(`${baseUrl}/api/uploads/images`, {
  method: 'POST', headers: { Authorization: `Bearer ${token}` }, body: form
});
const payload = await upload.json();
// 先检查 upload.ok && payload.code===0，再取 payload.data.imageUrl
```

图片 GET 同样需鉴权，普通 `<img src="后端imageUrl">` 不会自动加 Bearer。用带鉴权的 fetch 取得 Blob，再 URL.createObjectURL(blob) 给 img；组件卸载、换图或退出时 URL.revokeObjectURL，避免内存泄漏。不能把 Token 放到 URL 查询参数中。附带 frontend-api.js 的 imageBlob() 已区分二进制成功与 JSON 错误。

## 7. 统计和超时规则

created 是提交量，按 createTime；completed 是学生确认关闭量，仅 CLOSED，按 closeTime，不是维修工提交完成的 DONE 数量。from 包含、to 排除；日期可用2026-10-15或带时区 ISO 时间。按用户选择“截至某天”查询时 to 传下一天00:00，不传当天23:59:59。通过 URLSearchParams 编码 +08:00 中的加号。from>=to 返回400。

维修工工作量和评分归最终 workerId；推荐分=100×完整技能标签命中−10×当前ASSIGNED/PROCESSING负载，接口已排序，管理员仍可手选任意启用维修工。

SLA 当前默认 HIGH=4h、NORMAL=24h、LOW=72h，从创建起算并固化 deadline，改派或驳回不延长。严格超过期限才超时。DONE/CLOSED 按 finishTime 判断，等待学生确认不计维修超时；驳回恢复 PROCESSING 并清空 finishTime，但保留最近记录和历史日志。

isCurrentlyOverdue 是当前还需处理的超时，用于红色待处理预警；isOvertime 是曾经超时，包括已结束工单，用于历史标签。scope=active 为当前预警，scope=history 为历史超时；即使扫描尚未执行，查询也返回有效判定。不要仅靠前端当前时间对所有状态统一判超时。

## 8. 当前能力边界与交付要求

当前没有：管理员全量列表/通用搜索、账号管理、用户姓名查询、注册/改密/Token刷新、维修中改派、评价编辑/删除、独立消息中心、图片删除、批量操作、导出报表。不要自行请求推测的接口路径；新增能力先形成前后端接口变更记录。

前端可选择熟悉的框架；原交接建议 Vue + Element Plus + Axios，但不是当前后端的技术依赖。样式、字体、脚本和图标须本地提供，演示时断网可用，不引用 CDN。开发时先安装依赖，离线演示前完成构建并准备本地资源。

后端目前未配置静态前端托管。开发阶段用5173服务对接5000；最终同源部署到5000需要后端增加静态文件和前端路由回退，这属于后续联调工作，复制 dist 并不会自动生效。

输入描述/维修记录/评价等作为纯文本渲染，不使用未经处理的 innerHTML/v-html。适配 Chrome、Edge 和手机尺寸。普通页面小于2秒、约50人在线是后续实测目标，103项后端测试不能代替这些验收。

建议前端实施顺序：请求封装与登录 → 学生表单/图片 → 学生列表详情日志 → 管理员待派/维修工推荐 → 维修工接单完成 → 学生确认驳回评价 → 管理员统计评价/超时 → 轮询提醒、异常恢复、手机适配和离线验收。

## 9. 联调检查清单

1. 学生登录 → 读取选项 → 不带图提交 → 相同 key 重试只得到同一工单和一条 CREATE 日志。
2. 学生上传合法图并提交，图片能显示；超2 MiB、伪装格式、他人图片引用被拒绝。
3. 管理员登录 → 待派列表找到新单 → 推荐维修工 → 派单；学生调用派单返回403。
4. 指派维修工登录 → 列表找到工单 → 接单 → 填写记录提交完成；另一维修工处理返回404。
